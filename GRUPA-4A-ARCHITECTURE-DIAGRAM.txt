┌─────────────────────────────────────────────────────────────────────────────────┐
│                                EVENT FLOW SEQUENCE                              │
└─────────────────────────────────────────────────────────────────────────────────┘

Step 1: USER TYPES PICKUP ADDRESS
────────────────────────────────────
Input: "ul. Długa 1, Gdańsk"
   │
   ▼
handleAddressChange() [debounced 800ms]
   │
   ▼
detectAndSetPickupCity("ul. Długa 1, Gdańsk")
   │
   ├─► Validators.extractCityFromAddress() → "gdansk"
   │
   └─► cityMatchingService.setPickupCity("gdansk")
          │
          └─► Triggers EVENT: 'pickupCityChanged'
                 { cityId: "gdansk",
                   allowedDeliveryCities: ["gdansk", "gdynia", "sopot"] }


Step 2: ADDRESSFORM RECEIVES EVENT
────────────────────────────────────
onPickupCityChanged({ cityId: "gdansk", allowedDeliveryCities: [...] })
   │
   ├─► Store: this.allowedDeliveryCities = ["gdansk", "gdynia", "sopot"]
   │
   ├─► updateLocationIQAutocomplete(allowedCityIds)
   │      │
   │      └─► Remove old suggestions dropdown
   │      │
   │      └─► setupLocationIQInputWithFilter(input, allowedCityIds)
   │             │
   │             └─► Pass filter to LocationIQ:
   │                 locationIQ.autocomplete(query, ["gdansk", "gdynia", "sopot"])
   │
   └─► showCityHint(["gdansk", "gdynia", "sopot"])
          │
          └─► Display: "📍 Dostawa dostępna w: Gdańsk, Gdynia, Sopot"


Step 3: USER TYPES DELIVERY ADDRESS
────────────────────────────────────
Input: "ul. 10 Lutego 1, Gdynia"
   │
   ▼
handleAddressChange() [debounced 800ms]
   │
   ▼
detectAndSetDeliveryCity("ul. 10 Lutego 1, Gdynia")
   │
   ├─► Validators.extractCityFromAddress() → "gdynia"
   │
   └─► cityMatchingService.setDeliveryCity("gdynia")
          │
          └─► Validates: "gdansk" + "gdynia" → COMPATIBLE ✅
                 │
                 └─► Triggers EVENT: 'deliveryCityChanged'
                        { cityId: "gdynia",
                          validation: { valid: true, message: "✅ Dostawa możliwa..." } }


Step 4: ADDRESSFORM RECEIVES VALIDATION SUCCESS
────────────────────────────────────────────────
onDeliveryCityChanged({ cityId: "gdynia", validation: { valid: true } })
   │
   └─► clearCityError()
          │
          └─► Hide error banner if visible


Step 5: PRICE CALCULATION CALLBACK
───────────────────────────────────
onAddressChange(pickup, delivery)
   │
   └─► Triggers callback to PriceCalculator
          │
          └─► Calculate distance, price, display map

┌─────────────────────────────────────────────────────────────────────────────────┐
│                         PERFORMANCE OPTIMIZATION                                │
└─────────────────────────────────────────────────────────────────────────────────┘

1. DEBOUNCING
   ├─► Main handleAddressChange: 800ms (prevents excessive API calls)
   ├─► LocationIQ autocomplete: 300ms (balances UX vs API usage)
   └─► Result: ~90% reduction in API calls vs no debouncing

2. CACHING
   ├─► this.allowedDeliveryCities stored in component
   ├─► LocationIQ autocomplete cache (in LocationIQService)
   └─► Result: No recalculation on repeated queries

3. LAZY EXECUTION
   ├─► City detection only on address change
   ├─► Autocomplete update only when needed
   └─► UI updates only when state changes

4. CONDITIONAL CHECKS
   ├─► if (this.googleMapsService && this.googleMapsService.locationIQ) { ... }
   ├─► if (!deliveryInput) return;
   └─► Result: No errors if services unavailable


┌─────────────────────────────────────────────────────────────────────────────────┐
│                           EDGE CASES HANDLED                                    │
└─────────────────────────────────────────────────────────────────────────────────┘

1. City not detected from address
   └─► Reset state, clear hints, allow all cities

2. LocationIQ service not available
   └─► Skip autocomplete update, no errors thrown

3. DOM elements not found
   └─► Early return, graceful degradation

4. Multiple event listener registrations
   └─► Remove old suggestions before creating new

5. Null/undefined city IDs
   └─► Reset to default state, log warning

6. Rapid typing (race conditions)
   └─► Debouncing prevents multiple simultaneous requests

7. CityMatchingService not loaded
   └─► Constructor fails gracefully, app continues
